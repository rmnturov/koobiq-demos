# Меню с переходами

Демка `/demo/drilldown-menu` содержит отдельный составной компонент, предназначенный для последующего переноса в Koobiq Angular Components. Локальные имена `demo-*` отделяют его от установленного пакета.

## Подключение экранов

Компоненты — standalone. Импорты: `DrilldownMenu`, `DrilldownMenuScreen`, `DrilldownMenuTrigger`, `DrilldownMenuList`, `AutoRefreshMenu` из соответствующих локальных файлов, а также нужные компоненты Koobiq.

```html
<button kbq-button [drilldownMenuTriggerFor]="menu">Параметры</button>

<demo-drilldown-menu #menu="drilldownMenu" [maxHeight]="480" [width]="320">
  <ng-template drilldownMenuScreen="root" title="Параметры" let-api>
    <div drilldownMenuList aria-label="Параметры">
      <demo-auto-refresh-menu
        [(value)]="period"
        [presets]="presets"
        [defaultValue]="300000"
      />
      <kbq-divider />
      <button kbq-dropdown-item id="custom-opener" role="menuitem"
        data-drilldown-target="custom"
        (click)="api.navigate('custom', $any($event.currentTarget))">
        Свой раздел
      </button>
    </div>
  </ng-template>

  <ng-template #customActions>
    <button kbq-button (click)="save()">Сохранить</button>
  </ng-template>
  <ng-template drilldownMenuScreen="custom" title="Свой раздел"
    [screenWidth]="360" [headerActions]="customActions">
    <!-- Произвольные компоненты и собственная логика; форма не оборачивается в role=menu. -->
    <kbq-form-field><input kbqInput aria-label="Название" [(ngModel)]="name" /></kbq-form-field>
  </ng-template>
</demo-drilldown-menu>
```

`period` — сигнал или поле типа `number | null`. Число задает миллисекунды, `null` отключает обновление. Пример `presets`: `[{ value: 15000, label: '15 с' }, { value: 60000, label: '1 мин' }]`.

Порядок шаблона определяет порядок пунктов. Готовый блок можно убрать или переместить; разделители — обычные `kbq-divider`. Для нескольких блоков задаются разные `screenId`. Переходы сохраняют представления и состояние посещенных экранов до закрытия панели.

`drilldownMenuList` работает с настоящими `KbqDropdownItem`. Если пункт находится внутри собственного дочернего компонента, этот компонент регистрирует его через `list.registerItem(item)` и вызывает возвращенную функцию при уничтожении; готовый AutoRefreshMenu делает это сам. Для пунктов нужны устойчивые уникальные DOM id. Список сам поддерживает tabindex; дополнительная остановка для каждой строки не нужна.

## Публичный контракт

| API | Поведение |
| --- | --- |
| `rootScreen` | Идентификатор начального экрана; по умолчанию root |
| `maxHeight` | Максимальная высота вместе с шапкой; по умолчанию 480 px, дополнительно ограничена окном |
| `width`, `screenWidth` | Ширина контейнера и переопределение для экрана; по умолчанию 320 px |
| `initialFocus` | CSS-селектор начального пункта списка |
| `headerActions` | Angular-шаблон действий шапки, в контексте доступен let-menu |
| `open()`, `navigate(id, opener)`, `back()`, `close(reason)` | Открытие, переход, возврат и закрытие |
| `opened`, `closed` | События открытия и закрытия; closed передает причину |
| `value`, `valueChange` | Значение автообновления и его изменение; доступна запись [(value)] |
| `presets` | Настраиваемые периоды с подписями; отключение всегда отображается первым |
| `defaultValue` | Период для сброса; undefined скрывает кнопку, null сбрасывает в отключенное состояние |
| `formatPeriod` | Форматирование значения, которого нет среди пресетов |

Положительные конечные периоды сортируются по возрастанию. При повторяющемся значении сохраняется первая подпись. Значение, которого нет среди пресетов, сохраняется без отметки другого варианта. Сброс оставляет внутренний экран открытым; выбор периода возвращает в корень. Компонент не запускает таймер и не выполняет запросы.

## Управление с клавиатуры

Действия шапки входят в последовательность Tab отдельно, список — одной остановкой с roving focus. Начальный фокус корня — первый доступный пункт; автообновления — текущий период. Выбор и возврат восстанавливают фокус на открывшем раздел пункте. Если он удален, используется доступная цель текущего экрана.

| Клавиша | Действие |
| --- | --- |
| Tab, Shift+Tab | Перемещает фокус по шапке и списку. Циклически перемещает фокус внутри текущего экрана. После последней остановки переходит к первой, перед первой — к последней; панель остается открытой |
| Enter, Space | Активирует пункт |
| Esc | Возвращает в родительский экран; в корне закрывает панель и фокусирует кнопку открытия |
| ↓, ↑ | Перемещает фокус между доступными пунктами без изменения выбора |
| → | Открывает раздел пункта с data-drilldown-target |
| ← | Возвращает в родительский экран с фокусом на открывшем разделе пункте |
| Home, End | Перемещает фокус к первому или последнему доступному пункту |

Навигация нециклическая. Стрелки пользовательских полей и вложенных компонентов не перехватываются. Вложенный popup должен первым обработать Esc. Для принадлежности вынесенного popup используются aria-controls или aria-owns на его триггере.

Шапка находится вне прокручиваемой области, полоса KbqScrollbarViewport накладывается поверх содержимого. Переходы занимают 200 мс; reduced motion и отключение анимаций Koobiq применяются без ожидания таймера. Размеры панели меняются отдельно от transform содержимого, без масштабирования текста.

## Проверка

Проверено 21 ноября 2026 года:

- Все 33 целевых теста демки и реестра проходят; проверены навигация, сохранение представлений, фокус, Tab, пресеты, сброс, состав меню, изменение ширины экрана и начальный фокус пользовательской формы.
- Провайдер Koobiq с animationsDisabled и helper переходов проверены без ожидания анимации. Системный prefers-reduced-motion учтен в CSS и логике переходов; смена системной настройки в браузере отдельно не эмулировалась.
- Сборка и четыре теста упаковщика проходят; zip содержит menu/ и auto-refresh/.
- В браузере проверены светлая и темная темы, строки 32 px и шапка 40 px, пределы высоты 480 и 240 px, короткое окно и длинный список из 40 периодов. Полоса Koobiq накладывается поверх содержимого; шапка остается на месте, End показывает последний пункт.
- Реальные нажатия Tab и Shift+Tab проходят через Назад, Сбросить и одну остановку списка. Выбор возвращает фокус в корень, Esc закрывает по уровням. Tab и Shift+Tab ходят по кругу внутри текущего экрана и не закрывают панель.
- После исправления замечаний ревью проверены реальные координаты экрана относительно панели: 320 → 315 → 302 → 281 px, одновременно с изменением высоты 427 → 424 → 418 → 408 px. Горизонтальная прокрутка панели остается нулевой. Неподвижный указатель не меняет выбранный период. Быстрое чередование направлений сохраняет текущий экран и фокус; ошибок в консоли нет.
- Проверены имена экранов и состояние выбранного периода в дереве доступности. Отдельная проверка VoiceOver не выполнялась.

Полный прогон содержит четыре существующих сбоя, воспроизведенных на исходной ревизии 0ee289d с теми же установленными зависимостями: old-field.spec.ts — pastes 14:30, keeps the field untouched on an empty paste, rewrites the glued digits of a two-line paste on blur; panel.component.spec.ts — shows the mask when the view is empty. Оба файла находятся в timepicker-compare. Эти тесты и их реализация не изменены.

Сборка также сохраняет предупреждения каталога о размере начального bundle и CommonJS в @messageformat/core, а компилятор — существующие предупреждения шаблона timepicker-compare. Стили новой панели с миксинами Koobiq занимают 14,78 kB: это выше предупредительного бюджета 8 kB и ниже предельного 16 kB. jsdom сообщает о неподдерживаемом синтаксисе части CSS Koobiq; внешний вид проверен в браузере.

Независимое ревью выявило десять существенных замечаний. Все исправлены и покрыты регрессионными тестами; замечания к реальному движению и неподвижному указателю дополнительно проверены в браузере. Полный финальный прогон: 737 успешных тестов и четыре исходных сбоя, перечисленных выше. Отложенных замечаний нет.

Пункты используют FocusMonitor с preventScroll, а раскрытие пункта в видимой области выполняет собственный KbqScrollbarViewport. Это исключает прокрутку внешних предков через scrollIntoView во время перехода. Оболочка использует overflow:clip; viewport позиционируется относительно себя, как требует расчет смещения в scrollToElement.
