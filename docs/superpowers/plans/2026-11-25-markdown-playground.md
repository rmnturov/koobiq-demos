# Полигон Markdown — план реализации

> Для выполнения по шагам использовать `superpowers:executing-plans` или `superpowers:subagent-driven-development`.

**Цель.** Открыть из каталога одну прокручиваемую страницу с опубликованным Markdown Koobiq, чтобы сравнивать интервалы на воспроизводимых примерах.

**Устройство.** Статья, чейнджлог и образцы хранятся как Markdown-строки. Standalone-компонент передаёт каждую строку целиком в `KbqMarkdown`. Реестр приложения предоставляет маршрут, оболочку, переключатель темы и скачивание ZIP.

**Стек.** Angular 21, `@koobiq/components/markdown` и `marked` из lock-файла проекта.

**Основание.** [Согласованная спецификация](../specs/2026-11-25-markdown-playground-design.md).

## Общие ограничения

Первый этап воспроизводит стили библиотеки. Будущие правки и вариант 14 px используют тот же корпус. Подписи к проверочным примерам находятся за пределами компонента. Стили оболочки ограничены страницей демо.

## На что обратить внимание

- Все три элемента каждой комбинации должны оказаться соседями в одном выводе Markdown.
- Для H1–H6 проверяется иерархия реальных тегов.
- Два блока кода подряд должны разбираться как два отдельных блока.
- Оба способа подписи должны создавать ожидаемый DOM и показывать одинаковый рисунок.
- При смене темы, узком окне и прямом переходе по адресу все образцы должны оставаться доступны.
