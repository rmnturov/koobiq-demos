# Проверка демо автообновления

Дата: 23 ноября 2026 г. Адрес: `/demo/grid-auto-refresh`.

Реализованы локальный случайный поток, отдельный контроллер обновления и интерфейс на публичных компонентах Koobiq. Бесконечная прокрутка добавляет блоки по 50 строк из примененного снимка; AG Grid виртуализирует видимые строки.

## Проверки

- Чистая установка `npm ci --no-audit --no-fund` успешна.
- 29 новых проверок модели, сервера, контроллера и фильтров проходят; вместе с 6 проверками реестра — 35.
- Полный набор: 739 успешных, 4 ошибки. Ошибки совпадают с исходной проверкой: три сценария вставки старого таймпикера в `old-field.spec.ts` и пустая маска в `panel.component.spec.ts`.
- Проверки скриптов: 4 успешных.
- Сборка успешна. Остаются предупреждения о бюджете начального пакета (1,96 МБ при пороге предупреждения 1 МБ), CommonJS в date-formatter и двух выражениях таймпикера.
- Браузер: автоматическое поступление, защищенный счетчик, неизвестное количество, ошибка и восстановление, явное обновление, сохранение карточки и сброс дальнего выделения, фильтр статуса, сортировка и открытие карточки клавишей Enter.
- Браузер: PageDown подгружает второй блок до 100 строк; одновременно в DOM было 39 строк. Шапка сохраняет положение.
- Браузер: Topbar и ActionsPanel переносят действия в «Ещё»; вложенная настройка и скрытое массовое действие работают. Светлая и темная темы проверены. Ошибок в консоли нет.
- При ширине рабочей области 746 px открытая панель оставляет списку 320 px, настройки доступны. Ниже 600 px карточка занимает рабочую область, список временно inert; закрытие возвращает список. Временные размеры браузера сброшены.

## Ревью и решения

Независимое ревью выявило три существенных замечания; все исправлены:

1. Возврат поиска к примененному значению до ответа теперь отменяет устаревшую выборку. Добавлена проверка с отложенным ответом.
2. Ответ начатой проверки после выключения или скрытия вкладки сохраняет обнаруженные записи без автоматической вставки. Добавлены обе проверки.
3. Клавиатурные обработчики публичного API AG Grid открывают карточку и запускают управляемую сортировку из фокуса ячейки/заголовка. Проверено в браузере; `aria-sort` восстанавливается после внутреннего обновления AG Grid.

Дополнительные вопросы ревью закрыты так:

- Тема использует старое объявление peer-зависимости tokens 3. Узкое npm override сохраняет tokens 4 приложения; чистая установка, сборка и обе темы проверены.
- Пакет темы публикует ESM с импортами без расширений. Только этот пакет включен в `server.deps.inline` Vitest; проверка загрузки реестра использует настоящий модуль.
- Постоянный тост размещен локально под шапкой: глобальный ToastService не предоставляет нужную привязку. Постоянная polite live-region монтируется пустой и получает текст при обнаружении записей; отсчет секунд не озвучивается. Проверка экранным диктором отдельно не проводилась.
- Попытка полной отрисовки Koobiq/AG Grid в jsdom встретила ошибку вычисления CSS specificity в jsdom. Интеракции компонентов проверены в настоящем браузере; регрессионные проверки асинхронного поведения выполняются без подмены компонентов.
- Настоящий транспорт, изменения/удаление инцидентов и гарантии серверной пагинации вне согласованного объема.


## Уточнения после просмотра рабочего демо

- Применена `kbqAgGridThemeDisableCellFocusStyles`, как в `ag-grid-overview` и `ag-grid-and-content-panel`. Клавиатурная навигация сохранена.
- ID стал первой колонкой и ссылкой Koobiq с нативным подчеркиванием; название — обычный текст, дата — последняя колонка. Дата в гриде, карточке и статусе использует DateFormatter с Luxon-адаптером.
- Самодельный заголовок заменен стандартным AG Grid. Через `postSortRows` сохраняется примененный порядок до успешного ответа. Неудачная сортировка в браузере сохранила все проверенные пары row-index/ID и scrollTop 840,3 px.
- Измеренный зазор между гридом и Content Panel — 24 px. Все кнопки Topbar transparent.
- ActionsPanel открывается внутри gridArea поверх строк; при измерении ее нижний край был на 16 px выше нижнего края грида. Внешний padding грида — 0, запас 72 px находится внутри viewport по примеру документации.
- Клик по обычной ячейке обновляет активную карточку. Флажки изменяют только массовое выделение; ссылка ID и Enter открывают детали.
- После обновления новые ID первого блока получают временный фон `--kbq-background-theme-less`. CSS анимирует только прозрачность фонового слоя: 1,8 секунды удержания и 200 мс затухания. Отрицательная задержка от времени применения не дает виртуализированной строке начать отсчет заново; следующий блок не подсвечивается. Проверены голубой фон и opacity 0 после окончания.
- Общее CSS `scroll-behavior: smooth` конфликтовало с синхронной навигацией AG Grid и удалено. Плавно выполняется явное возвращение к началу через `scrollTo`; PageDown снова подгружает блок до 100 строк. Завершение контролирует публичный `bodyScrollEnd`, прерывание — pointerdown/wheel/touch/keyboard. В браузере возврат был прерван полосой прокрутки на промежуточном положении; режим остался защищенным.
- Проверки после изменений: 36 целевых (30 новых и 6 реестра), 4 проверки скриптов, production build — успешны. Полный набор: 740 успешных, те же 4 исходные ошибки таймпикера.

## Уточнение анимации новых строк

По обратной связи статическая голубая подсветка с затуханием заменена одним плавным импульсом: opacity 0 → 1 → 0 за 1 секунду, пик на 30% таймлайна. Применяется только к новым ID первого блока. Начальная загрузка и повторный рефреш без новых записей не подсвечиваются. Сохраняется абсолютный таймлайн при виртуализации и вариант для уменьшения движения. В браузере подтверждены отсутствие подсветки при запуске, промежуточная прозрачность при появлении и opacity 0 после завершения. Сборка и 18 проверок контроллера прошли.


## Вложенное меню сценариев

Пункты переполнения перенесены непосредственно в content родительского `kbq-dropdown`, как в `dropdown-nested`. Прежний внешний `ngTemplateOutlet` сохранял контекст объявления шаблона: триггер не получал родительский Dropdown через DI и открывал отдельное меню. Теперь нативная стрелка подменю, позиционирование рядом с пунктом, ArrowRight/ArrowLeft и закрытие после выбора работают. Это исправляет тот же контекст у вложенных настроек интервала и счетчика. Сборка успешна; поведение проверено в браузере.


## Закрепление чекбокса и ID

Для `selectionColumnDef` и колонки ID заданы `pinned: left`, `lockPinned`, `lockPosition: left` и `suppressMovable`. Использованы публичные свойства AG Grid: две колонки нельзя перетаскивать и откреплять, а незаблокированная колонка не может занять позицию между ними. При горизонтальной прокрутке на 286,6 px браузер подтвердил неизменные координаты обоих заголовков — 48,7 и 84,7 px. Ширины сохранились: 36 и 132 px. Сборка успешна.

## Тост ошибки внутри примера

Нижние самодельные сообщения заменены `KbqToastService`. Дочерний EnvironmentInjector предоставляет собственные Overlay и OverlayContainer внутри рамки примера; конфигурация TOP_RIGHT и отключение popover верхнего слоя сохраняют локальное позиционирование. Область массовых действий свободна. Подтверждения выдуманных действий используют тот же стек. Успешный запрос закрывает ошибку, повторная не дублирует активный тост. При уничтожении демо дочерний injector удаляет оверлей.

В браузере проверены настоящий error toast с подписью, одновременная ActionsPanel, штатное закрытие, повторный показ, закрытие после восстановления связи с сохранением выделения, подтверждение действия и отсутствие тостов после сброса. Ошибок в консоли нет. Production build и 36 целевых проверок прошли; предупреждения сборки прежние.

## Системная полоса под закрепленными колонками

Воспроизведено при горизонтальном переполнении: `.ag-horizontal-left-spacer` из AG Grid имеет `overflow-x: scroll`, хотя его `scrollWidth` и `clientWidth` равны (145 px до исправления). Это пустой компенсатор ширины закрепленных колонок в FakeHScrollComp, а не область данных. Тема Koobiq оформляет `.ag-body-horizontal-scroll-viewport`, но не spacer, поэтому браузер рисует у него системную полосу. Гипотеза о лишнем переполнении закрепленных ячеек не подтвердилась: размеры совпадают.

Локальное правило демо задает обоим горизонтальным spacer `overflow: hidden`. После исправления ширины равны 167 px, overflow обеих осей hidden. Основной viewport сохранил `overflow-x: scroll`, ширину 608 px при содержимом 907 px и успешно прокрутился на 298,5 px; закрепленная область осталась на x=48,7 px. Светлая и темная темы проверены, production build прошел.

Повторение регрессии: закрепить чекбокс и ID, сузить грид до горизонтального переполнения (либо открыть Content Panel), включить постоянный показ системных полос прокрутки и проверить пустую область снизу под ID. Для DOM-проверки у `.ag-horizontal-left-spacer` и `.ag-horizontal-right-spacer` должны совпадать scrollWidth/clientWidth и отсутствовать `overflow-x: scroll`; настоящий `.ag-body-horizontal-scroll-viewport` должен сохранять прокрутку. Проверять в браузере: jsdom не рассчитывает размеры и не рисует системные скроллбары. Данные до/после сохранены в артефактах `pinned-scrollbar-before.json` и `pinned-scrollbar-after.json`.

## Повторная проверка полосы при открытии Content Panel

Пользователь уточнил триггер: открытие Content Panel с появлением горизонтального скролла. В доступном браузере с предыдущим исправлением визуальный дефект повторно не проявился ни в пользовательской вкладке, ни при закрытии/открытии в отдельной проверочной вкладке. При этом у spacer по-прежнему вычислялись scrollbar-width auto и ::-webkit-scrollbar display inline.

Для этих двух служебных элементов дополнительно явно отключена отрисовка нативных полос: scrollbar-width none и ::-webkit-scrollbar display none. Основной viewport не изменен. После повторного открытия панели оба spacer имеют none/none; основной viewport — auto/inline, ширина 553 px при содержимом 907 px. Горизонтальная прокрутка проверена до 353 px, закрепленные колонки сохранили x=48,7 px. Сборка успешна. Результат измерений: `panel-scrollbar-reopen.json`, снимок с открытой панелью: `panel-scrollbar-fixed.jpg`.
