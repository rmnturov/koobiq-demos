# Полигон Markdown в Koobiq

Первый этап показывает, как опубликованный `KbqMarkdown` из зависимостей демо оформляет текст сегодня. Он нужен дизайнерам и разработчикам, чтобы находить проблемы с расстояниями и впоследствии оценить два набора типографики с основным текстом 16 и 14 px на одних и тех же примерах.

## Подход

Выбран штатный `<kbq-markdown [markdownText]="…">` со стилями установленной версии. Так любой спорный фрагмент можно воспроизвести в Angular Components с той же Markdown-строкой. Обсуждали локальную копию компонента: в ней проще менять генерируемый HTML, но её придётся сверять с библиотекой. К этому варианту можно вернуться, если для конкретной правки понадобится изменить разметку.

## Страница

Из каталога демо открывается «Полигон Markdown». На одной прокручиваемой странице идут три части.

1. **Статья.** Цельный русский текст с вводным абзацем, подзаголовками, ссылками, выделениями, вложенным списком, таблицей и иллюстрацией с подписью. Ориентир для структуры — [Article в shadcn Typeset](https://ui.shadcn.com/typeset).
2. **Чейнджлог.** Несколько записей с короткими заголовками, списками изменений, встроенным кодом и блоком кода. Он показывает, как выглядит плотный документ, в котором повторяется одна структура.
3. **Соседство элементов.** Короткие подписанные примеры из таблицы ниже. У каждого примера своя Markdown-строка. Все элементы внутри примера передаются в один экземпляр компонента, чтобы работали его правила для соседей. Подпись примера находится снаружи.

| Что смотрим | Примеры |
| --- | --- |
| Принадлежность заголовка | Абзац → заголовок → абзац для каждого уровня H1–H6. Блок кода → заголовок → абзац. Два последовательных заголовка разных уровней → абзац. |
| Границы блоков | Абзац → код → абзац, код → код, абзац → цитата → абзац, абзац → таблица → абзац, два абзаца с горизонтальным разделителем между ними. |
| Списки | Абзац → маркированный или нумерованный список → абзац. Вложенные списки разного типа, многострочный пункт, пункт с несколькими абзацами. |
| Изображение и подпись | Один рисунок со штатной подписью через соседний курсив и тот же рисунок в HTML-разметке `figure/figcaption`. За подписью идёт абзац. |
| Строка внутри абзаца | Ссылка, жирный, курсив, зачёркивание, встроенный код и явный перенос строки. |

## Что проверяем

Статья, чейнджлог и короткие примеры показывают типографику библиотеки в светлой и тёмной темах приложения. Оболочка демо отвечает за расположение образцов. Все внутренние отступы, включая спорные, берутся из компонента.

У тройки с заголовком сравниваем расстояние от предыдущего блока до заголовка и от заголовка до следующего блока. Желаемое поведение будущих стилей — второй промежуток меньше первого или равен ему. В первой версии расхождение служит наблюдением и остаётся видимым.

Компактные стили 14 px и правки базовых стилей относятся к следующему этапу. Для переноса в Angular Components экспериментальные правила будут собраны отдельно от оформления полигона. Тему статьи, текст записей и иллюстрацию выбирает разработчик.
